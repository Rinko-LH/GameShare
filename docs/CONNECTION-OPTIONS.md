# 房间与音视频连接

GameShare 各自建立房间信令和 WebRTC 音视频连接。信令负责入房、同步成员状态和交换连接信息。音视频由房间成员之间的 WebRTC 链路传输，网络条件和媒体策略决定它实际走哪条路径。

## 创建和加入房间

1. 房主打开「房间连接」，选择「创建房间」。昵称选填，客户端会在本机记住昵称。
2. 新用户可使用默认的「Cloudflare」和「自动协商」。同一局域网可把「用户连线方式」改为「IP直连」，选择朋友能访问的地址。
3. 点击「创建房间」。使用 Cloudflare 时，等临时网址就绪后点击「复制邀请」，将完整邀请私发给朋友。
4. 朋友在「房间连接」选择「加入房间」，粘贴到「房间邀请」，再点击下方的「加入房间」。客户端会使用邀请中的房间地址和连接设置。如果邀请指定了手动 IP，朋友须从列表里选择自己电脑的地址。
5. 入房后打开「屏幕共享」，点击「选择窗口或屏幕」开始分享，也可以先用静音的「测试源」确认画面能传到对方。

只有地址和房间码时，可以展开「手动加入」填写，画面声音传输通道须与房主一致。表单有邀请时会优先处理邀请，清空后可通过手填地址入房。改变连接配置前先离房。Tauri 会保存房主选择的连接配置，来宾的邀请和手动设置用于当前客户端会话。

## 用户连线方式

| Tauri 界面选项 | 房主准备 |
| --- | --- |
| Cloudflare | 客户端准备临时 HTTPS 网址。使用便携 ZIP 时完整解压，随附的 `cloudflared.exe` 放在主程序旁边。来宾直接使用邀请地址。 |
| IP直连 | 选择朋友可访问的本机地址。同一局域网选对应网卡，已用 UU 等工具组网可以选对应的虚拟网卡。有公网地址时需确认外网入站可达。 |
| 公网映射 | 填写端口映射或穿透工具给出的完整 HTTP(S) 访问地址，带上实际公网端口。外部服务须能转发 HTTP 和 WebSocket 到房主本机的信令服务。 |

房主连接自己的本机信令。Tauri 默认监听 TCP `8080`。端口已被使用时，客户端会检查现有服务的 `/health`，匹配 GameShare 服务后才复用，发现其他程序占用则会报错。

配置公网映射时，转发目标是穿透软件能访问的房主信令地址，例如同机代理使用 `http://127.0.0.1:8080`。填进 GameShare 的是朋友能访问的公网入口，例如 `https://room.example.com` 或 `http://203.0.113.10:18080`。创建房间后，让朋友从自己的网络访问入口的 `/health`，确认返回 `"ok": true` 和 `"service": "game-share-signaling"`。

Cloudflare 的临时网址由房主端维护。重开隧道后，房主应重新复制邀请。用完后可离房并点击「关闭临时邀请网址」，或退出房主客户端。

## 画面声音传输通道

| Tauri 界面选项 | 行为 | 适用场景 |
| --- | --- | --- |
| 自动协商 | WebRTC 使用本机候选和 STUN。如果房间信令服务提供兼容的 TURN 凭据，也会尝试使用中继候选。 | 同一局域网或异地组队时的默认选择。 |
| 手动指定 IP | 每个人选择自己电脑上对其他成员可达的媒体 IP。客户端限制发出的候选并检查实际路径，此模式关闭 STUN 和 TURN。 | 双方已经组网，希望使用特定网卡地址传输画面和声音。 |

使用 UU 等虚拟组网工具时，各成员选自己的组网地址。异地双方各自的局域网地址通常互不可达，即使 Cloudflare 信令可用。手动指定 IP 是实验功能。WebRTC 会在候选协商后核对实际地址，发现地址不符或持续无法核对时会停止相关媒体连接。所选 IP 消失时，客户端会停止媒体并保留房间连接。这个机制提供的是候选限制和运行时检查，核对之前仍可能经过其他地址。

STUN 用来发现公网映射地址。TURN 可以中继音视频，前提是房间信令服务能签发兼容的凭据。Tauri 内置信令目前不签发 TURN 凭据。通过 Cloudflare 临时网址交换信令时，受限网络仍可能需要组网或由兼容服务提供 TURN。

| 网络情况 | 用户连线方式 | 画面声音传输通道 |
| --- | --- | --- |
| 同一局域网 | IP直连 | 自动协商 |
| 异地，先尝试用临时入口 | Cloudflare | 自动协商 |
| 已有可用的端口映射或穿透地址 | 公网映射 | 自动协商 |
| 双方已用 UU 等工具组网 | IP直连，房主选自己的虚拟网卡地址 | 手动指定 IP，各自选自己的虚拟网卡地址 |
| 已组网，房间入口仍走公网 | Cloudflare 或公网映射 | 手动指定 IP，各自选自己的虚拟网卡地址 |

## 邀请兼容

当前邀请是 `GS3`，携带信令地址、房间码、信令方式和媒体策略。邀请不包含房主的本机媒体 IP 或 TURN 密钥。只理解 `GS1` 或 `GS2` 的旧客户端需升级后使用新邀请。

当前客户端可读取受支持的 `GS1` 和 `GS2` 邀请。旧版「局域网 / UU 自动连接」策略也可从既有偏好和邀请恢复，此策略只使用本机候选。Tauri 目前提供「自动协商」和「手动指定 IP」两种按钮供新房间主动选择。旧邀请未注明策略时，建议请房主重发，或按提示核对双方配置。

入房失败、已入房但看不到画面、或需要确认实际用了哪条路径时，按 [跨网络连接测试](REMOTE-TESTING.md) 排查。邀请字段与兼容逻辑见[邀请编解码](../apps/desktop/src/invitations.ts)。
