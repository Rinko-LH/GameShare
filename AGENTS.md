# Project instructions

- Before implementing a user request, briefly suggest how to express it clearly for the programming team, including useful acceptance criteria. Then continue the authorized work.
- Only create release packages when the user explicitly asks to package or publish a build. Do not package automatically after edits, fixes, tests, or builds used for verification.
- Release artifacts belong under `D:/GameShare/release` (the repository sibling `../release`). Do not create new release folders under `apps/desktop`.
- Ordinary work may run relevant checks and compile when needed; compilation is not permission to produce a distributable package.
- Do not move or delete existing release artifacts unless requested.
